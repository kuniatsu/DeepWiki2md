This document provides a high-level introduction to the online-doctor repository, a NestJS-based backend system for a healthcare platform. It explains the system's purpose, architecture, and core components.

For detailed information about specific subsystems, see: environment configurations (#3.2), deployment procedures (#5), API endpoints (#6), and external integrations (#7).

Purpose and Scope

The online-doctor system is a cloud-native healthcare backend application that manages:

  • Vital signal processing from video data via external medical APIs
  • Invoice generation and delivery with PDF creation and email notifications
  • Clinic administration including billing registration and profile management
  • Background job processing for asynchronous tasks such as data synchronization and email delivery

The application runs in two distinct modes:

  1. Main API Server (dist/main.js) - RESTful API for client applications
  2. Job Processor (dist/job.js) - Background task execution using Bull queues

Both modes share the same codebase but have separate entry points and can be deployed independently.

Application Entry Points

The application has two distinct runtime modes, each with its own entry point:

ModeEntry FilePurposeStart Command Example
API Serversrc/main.tsServes REST API endpoints, handles HTTP requestsNODE_ENV=prod node dist/main
Job Processorsrc/job.tsExecutes background jobs from Bull queuesNODE_ENV=prod node dist/job

Both modes:

  • Bootstrap the same AppModule
  • Load environment-specific configurations via NODE_ENV
  • Connect to the same MySQL database and Redis instance
  • Share all business logic, entities, and service classes

The separation allows horizontal scaling of API serving and background processing independently.

Deployment Environments

The system supports six distinct deployment environments, each with isolated AWS resources and database instances:

DemodemodemoClient demonstrations
StagingstgstagingPre-production validation
Staging Enhancestg-enhancestagingA/B testing variant
ProductionprodproductionLive system

Environment selection is controlled via the NODE_ENV environment variable, which determines:

  • Which configuration file to load from config/env/
  • AWS resource names (S3 buckets, DynamoDB tables)
  • MySQL database connection parameters
  • Redis cache endpoints

Start commands for each environment:

# API Server
NODE_ENV=local nest start --watch
NODE_ENV=dev node dist/main
NODE_ENV=prod node dist/main
 
# Job Processor
NODE_ENV=local node dist/job
NODE_ENV=dev node dist/job
NODE_ENV=prod node dist/job

External Service Integrations

The system integrates with multiple external services to provide its functionality:

Integration purposes:

  • S3: Store uploaded files, generated invoice PDFs
  • DynamoDB: Centralized audit trail for all API operations
  • SES: Send invoice emails to clinics, system notifications to support
  • Redis/ElastiCache: Bull job queue, session management
  • MySQL: Primary relational data store (clinics, invoices, PICs, vital signals)
  • SGI Tech: Computer vision API for extracting vital signs from video
  • WordPress: Legacy clinic management system integration
  • Medicom HR: Employee directory and authentication

For detailed integration specifications, see External Integrations.

Getting Started

To begin working with this codebase:

  1. Prerequisites: Install Node.js 16, MySQL, Redis, Docker (see Prerequisites)
  2. Environment Setup: Configure local environment variables (see Local Development Setup)
  3. Installation: Run yarn install to install dependencies
  4. Database: Execute migrations with yarn migration
  5. Running: Start the API server with yarn start:local

For comprehensive setup instructions, see Getting Started.
